# 通用线上 URL 打包器规范

## 需求：必填打包资料

打包器 MUST 要求 URL、产品标题和图标才能创建构建任务。

### 场景：资料完整

- **当** 用户提供 HTTPS URL、1–80 字符标题和支持的 PNG/ICO 图标
- **那么** 打包器允许选择架构并提交构建

### 场景：资料缺失或无效

- **当** URL、标题或图标任一缺失，或 URL 不是 HTTPS
- **那么** 打包器拒绝提交并指出无效字段

## 需求：默认 Windows x64

打包器 MUST 默认选择 Windows x64，并允许用户改选 x86。

### 场景：未选择架构

- **当** 用户提交未明确设置架构的有效资料
- **那么** 云端构建 `x86_64-pc-windows-msvc` 安装包

### 场景：选择 x86

- **当** 用户明确选择 x86
- **那么** 云端构建 `i686-pc-windows-msvc` 安装包，且产物名称表明 x86

## 需求：隔离的编译期配置

打包器 MUST 为每个构建 profile 生成独立的 Tauri 编译期配置。

### 场景：两个不同产品资料

- **当** 两个任务提供不同 URL、标题或图标
- **那么** 其安装包分别使用各自的配置，互不复用或泄露对方资料
